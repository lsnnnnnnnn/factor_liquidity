# 本轮材料怎样使用

先读同目录的 [实验报告](README.md)。它先说明实验设置、VWAP、共享成交额度与共享现金，再分别说明12股和30股样本的收益、完成情况及月度变化；已知数据边界集中放在最后。

本目录是追加实验材料。仓库原有 `tex_bundle/main.tex`、PDF和合成实验图表没有改动。这里包含六组PNG／矢量PDF、对应的最小绘图CSV、两份回测配置和重画脚本，不包含公司原始分钟行情或完整逐笔账本。

## 只看结果与重画图

`figures/tail/` 为12股补足观察期，`figures/expanded/` 为30股扩展样本。每个目录包括累计与月度汇总、标准化净值、匿名执行观察和指标口径。匿名观察仅保留分组、资金、参与率、观察期限、余量和完成交易分钟，用来重画完成率与用时图。

已有Python 3.11+环境时，在本目录执行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
MPLCONFIGDIR=.cache/matplotlib .venv/bin/python scripts/make_figures.py --output figures/tail
MPLCONFIGDIR=.cache/matplotlib .venv/bin/python scripts/make_figures.py --output figures/expanded
```

绘图需要中文字体，脚本会寻找Fandol或常用中文字体；也可通过 `--font /path/to/font.otf` 指定。不需要数据库或完整回测引擎。

## 运行回测与修改程序

源码在[目标仓库的本轮功能分支](http://172.16.10.26/lishengen/factor-liquidity/-/tree/codex/real-benchmark-study)，提交为 `e206804`。完整源码、依赖环境、已授权样本和结果另保存在本机桌面的 `factor-liquidity-real-study-20261016` 文件夹中。

进入源码目录后，先读 `docs/real_comparison_usage.md`。双击 `运行对照实验.command` 默认重跑12股版本；终端执行 `bash 运行对照实验.command expanded` 重跑30股版本。输出使用新的独立目录，不覆盖本轮结果。30股完整矩阵需要较长时间。

手动运行的关键命令为：

```bash
PYTHONPATH=src MPLCONFIGDIR=.cache/matplotlib .venv/bin/python -m pytest -q
PYTHONPATH=src MPLCONFIGDIR=.cache/matplotlib .venv/bin/python -m factor_liquidity.comparison --config configs/company-tail-study.yaml --output outputs/my-tail-study
PYTHONPATH=src MPLCONFIGDIR=.cache/matplotlib .venv/bin/python -m factor_liquidity.comparison_plots --output outputs/my-tail-study
```

改因子看 `strategy.py`，改资金、参与率、调仓和费用看配置；订单、现金、持仓、费用、公司行动与净值的处理看 `execution.py`，独立核对看 `audit.py`。收益和订单对照在 `comparison.py`，图表在 `comparison_plots.py`。

每组完整输出有订单、成交、持仓、每分钟净值、公司行动明细及 `audit.json`。本目录的CSV只够重画与复核汇总，不能单独重跑策略。

## 实际验证记录

- 全套309项测试通过；手算案例实际成交10,000、5,000、5,000股，最终现金100,000元、持仓20,000股、净资产300,000元，审计通过。
- 固定种子30股80日合成实验的25个情景审计通过，原有10%参与率结果得到复现。
- CSV／Parquet各3个文件输入情景，共6份审计通过，汇总数值一致。
- 两批真实对照各30组，共60份审计通过、149,075笔成交。逐组核对现金、持仓、应收、股息、送转及月度复利收益。
- 两批都没有样本期限截断订单；这只说明日历覆盖了执行期限，不证明分钟行情没有缺口。

完整矩阵保留启动时的代码版本及未提交状态记录。执行性能优化用同一完整真实情景逐列对照过，财务数值一致；没有把之后的提交信息反写成运行时的干净版本。

最低收益、最低成交完成率和最大延迟要求都未设置，容量状态仍为 `threshold_not_set`。本轮得到的是这些固定样本和明确模型下的实验结果，不据此给出资金容量上限。

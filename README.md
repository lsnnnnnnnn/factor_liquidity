# 30 只股票的 L2 买卖模拟

这次想回答一个问题：**同样一份买卖计划，资金增加以后，半小时、一小时和当天结束时，分别能完成多少？** 我们用真实 L2 快照中的十档买卖价格和挂单数量模拟成交，再看成交价格、等待时间和当天账户结果有什么变化。

[中文报告](l2_tex_bundle/report.pdf) · [可编辑正文](l2_tex_bundle/main.tex) · [完整 TeX bundle](dist/factor_liquidity_l2_tex_bundle.zip) · [编译与复现](l2_tex_bundle/README.md) · [图表数据说明](l2_tex_bundle/data/README.md)

先用 2026 年 3 月的成交额，把股票按成交活跃程度分成高、中、低三组，每组取 10 只。这 30 只都来自深圳 000 代码股票，不能代表全部 A 股。原计划从 2026-07-01 到 09-30，在每周第一个交易日各做一次当天的买卖比较，共 14 次。每次都重新设定初始持仓和现金；下周再从头做一次，不承接上周的持仓。

同一天、同一档资金下，要买卖的股票和股数先定好，随后不再改变。我们分别比较：假设全部按参考价成交；按真实盘口成交但不限制参与率；按真实盘口成交，并把参与率设为 5%/10%/20%。参与率越低，每次允许发出的数量越少。这样才能看出成交限制本身带来了什么差别。

实际取得 **1,678,487 条快照，覆盖 13 个日期、390 个有行情的股票日**。7 月 1 日这 30 只股票都没有 L2 数据，所以保留缺失记录，跳过当天的买卖比较。共运行 364 组比较，其中 325 组为主要结果，39 组用于查看延迟和盘口更新方式的影响；10,920 行订单结果全部通过账户核对，72 项引擎测试通过。

10% 参与率下，100 万元账户当天完成计划买卖金额的 **99.14%**。1 亿元账户在 30/60 分钟和当天结束时，分别完成 **65.14% / 72.70% / 86.19%**；其中买入完成 **80.55%**，卖出完成 **97.47%**，仍有 107 笔订单没有全部完成。

把 1 亿元账户在这 13 天各自的当天收益，与“全部按参考价成交”的结果相比，收益差的中位数为 **-0.6769 个百分点**。每一天都是重新开始的比较，不能把这些收益连起来当成季度累计收益。报告 PDF 已实际编译并逐页检查，共 6 页。

## 使用

已有 TeX Live / MacTeX（ctex、Fandol、latexmk、LuaLaTeX）时：

```bash
git clone --branch main https://github.com/lsnnnnnnnn/factor_liquidity.git
cd factor_liquidity/l2_tex_bundle
make pdf
```

仓库已附图表，只编译 PDF 不需要 Python 或数据库。使用 Overleaf 时，上传 ZIP 中 `l2_tex_bundle` 的内容，主文件选择 `main.tex`，编译器选择 **LuaLaTeX**。附带的 CSV 可以在不连接数据库的情况下重新画图。

`main` 保存这次 30 股研究。此前两股 L2 实验保存在 [`v2`](https://github.com/lsnnnnnnnn/factor_liquidity/tree/v2)，旧分钟 VWAP 报告与实验保存在 [`v1`](https://github.com/lsnnnnnnnn/factor_liquidity/tree/v1)；各版源码、数据、图和 PDF 都随对应分支保存。

选股先用未复权官方收盘价计算简单动量，还没有读取公司正式因子文件。原始 L2、完整账户、私有配置和凭据不进入公开仓库。30/60 分钟只是查看进度的时点；目前没有约定成交多少、用时多久、收益达到多少才算合格，因此不据此给出资金容量上限。
